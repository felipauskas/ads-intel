# Coverage notes: intentionally unreachable branches

Line numbers are for the files as they stand in this change set. Each entry
records *why* the branch cannot execute, so a future reader does not spend time
trying to write a test for it.

| Location | Branch | Why unreachable |
| --- | --- | --- |
| `sources.py:463-464` | `if id_idx < 0: return None` in `_parse_block` | `status_idx` is only set by `_status_index` (`sources.py:271-282`), which returns a status line index only when the first non-blank line in `lines[i+1:i+4]` is a `Library ID:` line. `_parse_block` then scans the same window (`status_idx+1 .. status_idx+3`), skipping nothing and checking every line, so it always finds that id at or before the index `_status_index` found. The miss branch cannot be taken. |
| `sources.py:889-892` | `elif decoded is not None: raise FetchError("malformed json")` in `_fetch_once` | `decoded` is assigned only from `json.loads(result)` and only when the stripped body starts with `{` or `[`. A top-level `{` that fails to decode raises earlier (`sources.py:867-871`); a top-level `[` that fails to decode leaves `decoded = None`. A successful decode of a body starting with `{` is always a dict, and of `[` always a list, so the two preceding branches (`isinstance(decoded, dict)` / `isinstance(decoded, list)`) cover every non-None value. Scalars, `null` and booleans are handled by the `_looks_like_json_scalar` branch, not here. |
| `store.py:357-359` | `unfiltered = _snapshot_path(query, country); if unfiltered not in paths: paths.append(unfiltered)` in `_snapshot_candidates` | Inside `if not scoped`, `scoped` is false only when the filters normalise to their defaults and `advertiser` is empty. `paths[0]` is built as `_snapshot_path(query, country, advertiser, active_status, media_type)` (`store.py:346-348`), and `_artifact_key` normalises all three extra components the same way, so with defaults and no advertiser it hashes the identical base string. The two paths are byte-identical, so `unfiltered not in paths` is always false and the append never runs. |
| `store.py:13-14` | `def _data_dir()` inside `try:` importing `plugins.plugin_storage` | The plugin runtime module `plugins.plugin_storage` is not installed in the test environment (`import plugins.plugin_storage` raises `ModuleNotFoundError`), so the module-level `try/except ImportError` always takes the dev fallback at `store.py:16-19` under pytest. The plugin-host definition is exercised only inside the real Hermes plugin runtime. |
| `tools.py:335` | `or {}` after the `store.load_snapshot(...)` call in the snapshot reader | `store.load_snapshot` is total: it returns the loaded dict or the literal `{"ads": {}}` (`store.py:400`). It never returns `None`, so the `or {}` fallback — and any test aiming at it — cannot be reached. It is kept as a defensive guard only. |
